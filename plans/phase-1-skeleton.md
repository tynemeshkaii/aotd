## 0. Технические решения (зафиксированы для фазы 1)

| Что | Выбор | Почему |
|---|---|---|
| Expo SDK | SDK 52 (или актуальный stable на момент старта) | Latest, поддержка new architecture |
| Язык | TypeScript (strict mode) | Меньше runtime багов, лучше autocomplete для Claude Code |
| Package manager | **npm** | Дефолт для Expo, меньше surprise. pnpm/bun добавляют риски совместимости с Expo plugins |
| Роутинг | **expo-router** (file-based) | Официальный Expo стандарт, как Next.js — папка `app/` определяет роуты |
| Стилизация | **NativeWind** (Tailwind for RN) | Стандартный синтаксис, Claude отлично пишет Tailwind, легко рефакторить. Альтернатива Tamagui — мощнее, но сложнее в подготовке и медленнее на старте |
| Иконки | `@expo/vector-icons` (встроены) | Не надо ничего добавлять |
| Server state | **@tanstack/react-query v5** | Стандарт, кэш, retry, idle/loading — всё из коробки |
| Client state | React useState + Context (пока хватит) | Zustand добавим если понадобится в фазе 3+ |
| Supabase client | `@supabase/supabase-js` v2 | Официальный |
| Auth storage | `expo-secure-store` (через адаптер для Supabase) | Безопасное хранение токенов в Keychain |
| Линтер/формат | **Biome** (одно в одном) | Быстрее и проще чем ESLint+Prettier. Без религии — если что, миграция тривиальна |
| Тесты | Не настраиваем в фазе 1 | Преждевременно. Добавим в фазе 4 (алгоритм) — там это нужно |
| Запуск на устройстве | **Expo Go** | Решено в обсуждении. Переход на dev build — в фазе 2 |
| Миграции Supabase | **Supabase CLI** + папка `supabase/migrations` | Версионирование схемы в git |
| Error tracking | **Sentry** (`@sentry/react-native` через `sentry-expo`) | С первого дня — иначе пропустим баги бети |
| Конфиги | `.env` локально, Expo `extra` в `app.config.ts` | Не коммитим секреты |

### Шаг 2 — TypeScript strict + Biome

1. В `tsconfig.json` поставить `"strict": true` и
   ```json
   {
     "compilerOptions": {
       "strict": true,
       "noUncheckedIndexedAccess": true,
       "paths": { "@/*": ["./*"] }
     }
   }
   ```
2. Установить Biome:
   ```bash
   npm install -D --save-exact @biomejs/biome
   npx biome init
   ```
3. В `biome.json` включить:
   - `formatter.indentStyle: "space"`, `indentWidth: 2`
   - `linter.rules.recommended: true`
   - игнор `node_modules`, `.expo`, `android`, `ios`
4. Добавить в `package.json` скрипты:
   ```json
   "scripts": {
     "lint": "biome check .",
     "format": "biome format --write ."
   }
   ```

**Точка проверки:** `npm run lint` проходит без ошибок.

   ```js

     content: ['./app/**/*.{ts,tsx}', './components/**/*.{ts,tsx}'],
     presets: [require('nativewind/preset')],
     theme: {
       extend: {
         colors: {
           bg: '#0a0a0a',
           surface: '#171717',
           text: '#fafafa',
           muted: '#737373',
           accent: '#1db954', // spotify-зелёный как акцент

       },
     },
     plugins: [],
   };
   ```
3. `global.css`:
   ```css
   @tailwind base;
   @tailwind components;
   @tailwind utilities;
   ```
4. В `babel.config.js`:
   ```js
   module.exports = function (api) {
     api.cache(true);
     return {
       presets: [
         ['babel-preset-expo', { jsxImportSource: 'nativewind' }],
         'nativewind/babel',
       ],
     };
   };
   ```

5. `metro.config.js`:
   ```js
   const { getDefaultConfig } = require('expo/metro-config');
   const { withNativeWind } = require('nativewind/metro');
   const config = getDefaultConfig(__dirname);
   module.exports = withNativeWind(config, { input: './global.css' });
   ```

6. Импортировать `global.css` в `app/_layout.tsx`.

### Шаг 7 — Supabase: проект + миграции

**В Supabase Dashboard:**
1. Создать проект `album-of-the-day` (регион — ближайший: `eu-central-1` или `eu-west-1`).
2. Сохранить `Project URL` и `anon public key` в `.env.local`.
3. Сохранить `service_role key` в **отдельный** файл `~/.supabase-aotd-service-role` (никогда не в репо, понадобится только для CLI/Edge Functions).

**Локально:**
1. Установить Supabase CLI: `brew install supabase/tap/supabase`
2. В корне проекта: `supabase init` (создаёт `supabase/config.toml`)
3. `supabase link --project-ref <ref>` — связать с облачным проектом
4. Создать миграцию: `supabase migration new initial_schema`
5. В сгенерированный файл `supabase/migrations/<timestamp>_initial_schema.sql` положить базовые таблицы (см. §3 ниже). На фазе 1 — только то, что понадобится в фазах 2–3 (минимум).
6. Применить: `supabase db push`
7. Сгенерировать типы:
   ```bash
   supabase gen types typescript --linked > types/database.ts
   ```
   Добавить в `package.json`:
   ```json
   "db:types": "supabase gen types typescript --linked > types/database.ts",
   "db:push": "supabase db push",
   "db:new": "supabase migration new"
   ```

### Шаг 8 — Минимальная схема БД для фазы 1

Фаза 1 не использует БД активно, но мы создаём фундамент. Полная схема из мастер-плана развёртывается частями: сейчас — то, что нужно для фаз 1–3.

```sql
-- supabase/migrations/<ts>_initial_schema.sql

-- Расширения
create extension if not exists "pgcrypto";

-- users (расширение auth.users через trigger создадим в фазе 2;
-- сейчас просто public.profiles с FK на auth.users)
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  display_name text,
  avatar_url text,
  timezone text default 'UTC',
  preferred_push_time time default '08:00',
  onboarding_completed boolean default false,
  created_at timestamptz default now()
);

alter table public.profiles enable row level security;

create policy "profiles_select_own" on public.profiles
  for select using (auth.uid() = id);

create policy "profiles_update_own" on public.profiles
  for update using (auth.uid() = id);

-- Auto-create profile при регистрации
create or replace function public.handle_new_user()
returns trigger as $$
begin
  insert into public.profiles (id) values (new.id);
  return new;
end;
$$ language plpgsql security definer;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure public.handle_new_user();
```

Остальные таблицы (`streaming_connections`, `user_library`, `albums`, ...) добавим в соответствующих фазах отдельными миграциями.

**Точка проверки:** в Supabase Dashboard → Table Editor видна таблица `profiles`. `supabase db diff` показывает пустой diff.

### Шаг 9 — Supabase client в приложении

```bash
npm install @supabase/supabase-js
npx expo install expo-secure-store
```

**`lib/supabase.ts`:**
```ts
import 'react-native-url-polyfill/auto';
import { createClient } from '@supabase/supabase-js';
import * as SecureStore from 'expo-secure-store';
import type { Database } from '@/types/database';
import { env } from './env';

const ExpoSecureStoreAdapter = {
  getItem: (key: string) => SecureStore.getItemAsync(key),
  setItem: (key: string, value: string) => SecureStore.setItemAsync(key, value),
  removeItem: (key: string) => SecureStore.deleteItemAsync(key),
};

export const supabase = createClient<Database>(env.supabaseUrl, env.supabaseAnonKey, {
  auth: {
    storage: ExpoSecureStoreAdapter,
    autoRefreshToken: true,
    persistSession: true,
    detectSessionInUrl: false,
  },
});
```

Не забыть: `npx expo install react-native-url-polyfill`.

**Точка проверки:** в любом экране вызвать `supabase.from('profiles').select('id')` — вернёт пустой массив (RLS пускает только своих, мы пока не залогинены — это нормально, не ошибка).

```ts
import * as Sentry from '@sentry/react-native';
import { env } from './env';

export function initSentry() {
  if (!env.sentryDsn) return;

    dsn: env.sentryDsn,

    tracesSampleRate: env.env === 'production' ? 0.1 : 1.0,
```

## 5. Риски фазы 1 и митигации

| Риск | Митигация |
|---|---|
| NativeWind v4 + Tailwind 3.x несовместимости | Точно следовать версиям из этой инструкции. Если что-то не работает — `npm ls tailwindcss` и проверка Expo SDK matrix в [nativewind docs](https://www.nativewind.dev/) |
| Supabase CLI требует Docker для local dev | Не используем local dev в фазе 1 — пушим миграции сразу в облачный проект (`supabase db push`). Docker не нужен. |
| `expo-router` typed routes ругаются на отсутствующие файлы | Создавать файлы экранов до их использования. Запускать `npx expo` после каждого добавления маршрута. |
| Случайно закоммитили `.env.local` | До первого push — проверить `git log --all --full-history -- .env.local`. Если попало — пересоздать ключи Supabase, force-overwrite branch. |
| Sentry DSN в `EXPO_PUBLIC_*` — это публичное значение, ок. Anon key Supabase — тоже ок (RLS защищает). | Service role key Supabase **никогда** не попадает в клиент. |

## 7. Что я (юзер) делаю руками заранее

Ещё до того как сядешь за Claude Code, чтобы не блокироваться:

1. **Установить Node.js LTS** с [nodejs.org](https://nodejs.org) (если ещё нет): `node -v` должен дать 20.x или выше.
2. **Установить Expo Go** на iPhone из App Store.
3. **Создать аккаунт Supabase** ([supabase.com](https://supabase.com)) и проект:
   - Name: `album-of-the-day`
   - Регион: ближайший
   - Database password: сгенерировать и сохранить в 1Password/менеджер
4. **Скопировать из Supabase → Project Settings → API:**
   - Project URL
   - `anon` public key
   - `service_role` key (в отдельный безопасный файл)
5. **Создать аккаунт Sentry** ([sentry.io](https://sentry.io)) → New Project → React Native → скопировать DSN.
6. **(Опционально) Создать GitHub репо** — пустой, мы запушим в него позже.
7. **Установить Supabase CLI**: `brew install supabase/tap/supabase` (или [инструкции](https://supabase.com/docs/guides/local-development/cli/getting-started)).

После этого — открываешь Claude Code в корне проекта и говоришь: _"Начнём фазу 1, шаг 1 по плану в plans/phase-1-skeleton.md"_.
